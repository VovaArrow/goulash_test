# Goulash · Поставщики — сервис поиска и сравнения поставщиков продуктов питания

Дата: 2026-10-22. Статус: одобрен Владимиром 22.10.2026.
Контекст: тестовое задание (часть 2) на вакансию AI-инженера в команду Ивана Зайченко (Goulash.Tech, Жизньмарт, Сушкоф). Текст задания — `test.md`. Исследование ниши и бизнеса — `docs/report.md`, болевые точки — `plan.md`.

## 1. Зачем это и для кого

**Пользователь:** руководитель отдела закупок или директор сети общепита/фудтеха (сеть доставки, фабрика-кухня, магазины готовой еды). Не «закупщик-исполнитель», а человек, который принимает решение, с кем работать.

**Момент использования:** появилась потребность в поставщике — новое блюдо, замена сорвавшегося или подорожавшего поставщика, открытие точек в новом городе, нужен запасной поставщик (на ключевую позицию держат 2–3). Сейчас это ручная работа: поиск в интернете/соцсетях, звонки, сбор прайсов в таблицу, отдельная проверка юрлица, отдельная проверка документов.

**Почему это важно именно этому бизнесу** (подробно — в `docs/report.md`):
- Жизньмарт пережил вспышку сальмонеллы у стороннего поставщика (2024) и закрытие магазина (09.2026). Основатель публично боялся, что тот же владелец вернётся через новые юрлица. → **надёжность поставщика важнее цены**.
- Сушкоф и Жизньмарт жаловались в ФАС на цены лосося (2022). Фудкост по рынку вырос до ~33%. 43% рестораторов в 2026 планируют искать альтернативных поставщиков. → **нужно быстро находить и сравнивать альтернативы**.
- При выходе в новый регион (Казахстан, ОАЭ) ассортимент и поставщиков собирают с нуля. → **поиск по городу/региону с учётом логистики**.
- В продукте Goulash.Tech модуля поставщиков/закупок публично нет. Рынок закрывает либо заказ у уже подключённых поставщиков (Saby, iiko), либо каталоги без проверки (Optlist, Supl.biz). → **ниша «найти + проверить + запросить КП» свободна**.

**Конечная цель одного сценария:** пользователь связался с 1–3 лучшими поставщиками и запросил у них КП. Сервис не ведёт дальнейший цикл (образцы → дегустация → пилот → договор) — это non-goal.

## 2. Цели, не-цели, анти-цели

**Цели**
1. Поиск по категории товара и городу/региону — запросом обычной фразой и/или фильтрами.
2. Шорт-лист, отсортированный по понятному баллу, с объяснением «почему он» и флажками рисков.
3. Карточка поставщика со всей собранной информацией и источниками.
4. Карта: где моя точка, где поставщики, расстояние — для логистики.
5. Сравнение 2–4 поставщиков в таблице с выводом простыми словами.
6. Запрос КП нескольким поставщикам одним действием (готовое письмо) + список отправленных запросов со статусами и заметками.
7. Объяснение, как сервис работает и как он будет работать в проде (реальные источники данных).

**Не-цели (в прототипе не делаем)**
- Реальные интеграции с внешними API (2ГИС, DaData, ФНС, ФСА, ВетИС) и реальная отправка писем. Данные — мок-база. Архитектура позволяет подменить мок на реальный источник.
- Авторизация, роли, мультитенантность.
- Ведение поставщика после получения КП (образцы, дегустации, договор, регулярные заказы).
- Деплой на сервер. Сейчас — запуск на localhost; Docker-файлы готовим, чтобы позже развернуть.

**Анти-цели (провал, даже если «работает»)**
- Ещё один каталог-«доска объявлений», где думать всё равно приходится самому.
- «Чёрный ящик»: балл без объяснения, откуда он взялся.
- Интерфейс, в котором руководитель теряется: перегруз полями, нужен онбординг.
- Демо, которое без интернета/ключа API не работает.

## 3. Решения, принятые Владимиром

- Главный экран — вариант B: запрос словами → критерии чипами → шорт-лист с баллом и объяснениями.
- К варианту B добавить **фильтры** и **карту** (удалённость важна для логистики).
- Конечная цель — **запросить КП / связаться** с поставщиком.
- Данные — **мок-база**, без настоящих интеграций. Ключей API нет.
- Формат — **веб-сервис**; сейчас **локально (localhost)**, чтобы было проще редактировать; позже — на сервер.
- **LLM API в этой версии не подключаем** — только правила, интерфейс оставляем под будущий LLM.
- **Ссылка на прототип при сдаче — localhost** (запуск одной командой по README).
- Визуал — **в стиле Goulash.tech** (скриншоты в `visual/`).
- Стек — на моё усмотрение.

## 4. Как это работает (пользовательский путь)

1. **Запрос.** Поле ввода: «Нужна моцарелла для пиццы в Екатеринбург, ~200 кг в месяц, обязательно декларации, желательно отсрочка 14 дней». Под полем — 3–4 примера-подсказки в один клик.
2. **Разбор запроса → чипы критериев.** Категория/товар, город + радиус, объём в месяц, ценовой потолок, обязательные условия (жёсткий фильтр) и желательные (влияют на балл). Любой чип удаляется/правится. Если что-то не распознано — сервис честно показывает «не понял: …».
3. **Результаты.** Три зоны:
   - слева фильтры (расстояние, цена, мин. партия ≤ моего объёма, документы, Меркурий, своя доставка, отсрочка, только производители, скрыть с критичными рисками, тип);
   - в центре шорт-лист: балл 0–100, название, расстояние и срок доставки, цена, мин. партия, 2–4 строки «почему» (✓ / ⚠ / ⛔);
   - справа карта: моя точка ★, поставщики (цвет = балл), при наведении/клике — подсветка в списке. Переключатель вида: Список / Карта / Список+карта.
   - сортировка: по баллу, цене, расстоянию.
   - приоритет пользователя: «Баланс / Надёжность / Цена / Скорость» — меняет веса балла.
4. **Карточка поставщика** (боковая панель или отдельная страница): реквизиты, тип, год основания; контакты, сайт, источники данных; расшифровка балла по 4 частям; ассортимент с ценами; условия (мин. партия, доставка, график, оплата/отсрочка); документы (декларации/сертификаты с датой окончания, Меркурий, ХАССП, Честный знак, халяль); проверка компании (возраст, сотрудники, выручка, суды, налоговый долг, массовый адрес, связи с ликвидированными/проблемными юрлицами); отзывы/заметки команды (можно добавить свою).
5. **Сравнение** 2–4 выбранных: таблица, лучшее значение в строке отмечено, внизу автоматический вывод простыми словами (например, «дешевле за кг, но мин. партия 300 кг при вашей потребности 200 кг»).
6. **Запрос КП.** Выбор поставщиков → письмо, собранное из запроса и профиля компании (кто мы, что нужно, объём, адрес, условия, нужные документы, просьба об образце). Текст редактируется. Каналы: e-mail (`mailto:`), WhatsApp (`wa.me` с текстом), Telegram (share-ссылка), «скопировать». Нажатие фиксирует запрос в системе.
7. **Вкладка «Запросы КП»:** поставщик, дата, канал, статус (Отправлено → Ждём ответ N дн. → КП получено / Отказ), цена из КП (вводится вручную), заметка. Статус меняется вручную. «Сравнить полученные КП» открывает то же сравнение. Есть несколько демо-запросов, чтобы вкладка не была пустой.
8. **Профиль компании** (небольшая форма): название сети, город, адрес точки/кухни (координаты — из справочника мок-адресов города), контакт для письма. По умолчанию — демо-профиль «Сушкоф и пицца, Екатеринбург».
9. **«Как это работает»:** страница/модалка — как устроены разбор запроса, балл, источники данных в проде, что мок, а что нет.

## 5. Балл и риски (логика)

Балл 0–100 = взвешенная сумма четырёх частей, каждая 0–100. Веса по умолчанию (режим «Баланс»): соответствие 30, надёжность 30, цена 20, логистика 20. Режимы меняют веса.
- **Соответствие запросу:** есть ли нужный товар (точное совпадение > категория), мин. партия ≤ объёма, выполнены ли желательные условия.
- **Цена:** цена поставщика относительно медианы по этому товару среди найденных (дешевле медианы → выше). Нет цены — нейтрально, с пометкой «цена по запросу».
- **Надёжность:** возраст компании, производитель/дистрибьютор, документы действуют, Меркурий, ХАССП, отсутствие судов/долгов/массового адреса/проблемных связей, отзывы.
- **Логистика:** расстояние от точки пользователя, срок доставки, своя доставка/холодовая цепь, покрывает ли регион пользователя.

Обязательные условия — жёсткий фильтр (кто не проходит, не попадает в список; счётчик «скрыто N, потому что …»).
**Флажки рисков:** ⛔ критичный (компания < 6 мес., налоговый долг, банкротство, связь с юрлицом с санкциями Роспотребнадзора, декларация просрочена) — при включённом фильтре такие скрываются; ⚠ предупреждение (дистрибьютор, мин. партия выше объёма, доставка > 2 дней, нет данных по документам); ✓ плюсы.
Каждая цифра балла раскладывается в карточке — никакого «чёрного ящика».

## 6. Архитектура

```
Браузер (SPA без сборки: HTML + Alpine.js + Leaflet, стиль Goulash)
        │  JSON
FastAPI (Python 3.12)
  ├── api/        — /search, /suppliers/{id}, /compare, /kp/draft, /kp, /profile, /meta
  ├── ai/         — QueryParser, Explainer, KPWriter: интерфейс + реализация RuleBased (правила, без API).
  │                 Интерфейс оставлен под LLM-провайдер — подключение описано в README как следующий шаг, в коде не реализуется
  ├── scoring/    — балл, веса режимов, флажки рисков, вывод сравнения
  ├── sources/    — интерфейс SupplierSource: MockSource (сейчас) | заглушки-описания для DaData/ФНС/ФСА/2ГИС
  └── db/         — SQLite, схема и SQL-запросы, сид мок-данных
```

- **Почему так (обоснование формата):** Python/FastAPI/SQL — стек из вакансии; SQLite — ноль настройки, файл в репозитории, легко заменить на Postgres; фронт без сборки — проще редактировать и запускать локально; Leaflet + OpenStreetMap — бесплатная карта без ключа. AI-слой за интерфейсом: сейчас работает на правилах, без внешних API; LLM-провайдер подключается позже одной новой реализацией интерфейса.
- **Мок-данные:** ~80–100 поставщиков, детерминированный сид-скрипт. Категории: молочка и сыры, мясо и птица, рыба и морепродукты, овощи/фрукты/зелень и нарезка, бакалея (рис, мука, масло), соусы и специи, готовая еда и полуфабрикаты (фабрики-кухни), хлеб и выпечка, напитки, упаковка и одноразовая посуда. Города: Екатеринбург (основной, больше всего данных), Челябинск, Тюмень, Пермь, Казань, Москва, Алматы, Астана. Есть специально «плохие» поставщики (молодое юрлицо, связи с проблемной компанией, просроченная декларация), чтобы флажки было видно. Источник каждого поля помечен (мок-«2ГИС», «сайт», «ЕГРЮЛ», «ФСА»).
- **Карта:** тайлы OSM требуют интернет; без интернета список и фильтры работают, карта показывает заглушку.
- **Запуск:** `make run` / `uvicorn` локально; `docker compose up` как вариант для будущего сервера.
- **Тесты:** pytest на разбор запроса, балл/флажки, ключевые эндпоинты.

## 11. UX-идеи у конкурентов (одобрено Владимиром — берём все 12)

Источник: `docs/research/competitors-ux.md`.
1. **«Почему он» / «На что обратить внимание»** — две колонки в карточке результата: плюсы с привязкой к запросу и рынку; минусы только ⚠/⛔ (Keychain).
2. **Проверка юрлица с вердиктом:** плашка «Надёжность: высокая/средняя/низкая», счётчики «⛔ · ⚠ · ✓», факты по группам (регистрация и возраст, налоги и долги, суды и банкротство, связи и адрес, документы на продукцию) со своим вердиктом, «данные на ДД.ММ.ГГГГ» (Rusprofile, Checko).
3. **Нижняя панель «Выбрано N из 4»** → Сравнить / Запросить КП; предупреждение, если у поставщика нет контактов (Thomasnet).
4. **Документы со сроком:** «действует до ММ.ГГГГ», ⚠ «истекает через N дн.» (≤ 30 дн.), просроченный — ⛔ (Keychain, Opply).
5. **Чипы — только сказанное пользователем;** предложения сервиса (например, «Меркурий» для молочки/мяса/рыбы, «холодовая цепь» для охлаждённого, «укажите объём») — пунктирные чипы, не применяются без клика (антипример — Alibaba AI).
6. **Источник и дата у каждого блока карточки;** пустые поля — «Нет данных — уточнить в КП», и эти пункты автоматически попадают в письмо КП (Thomasnet).
7. **Статусы КП шкалой + лента событий** с датами, «ждём ответ до …» (Opply, Kaspi).
8. **Один запрос КП — каждому в его канал:** у поставщика предпочтительный канал (WhatsApp/e-mail/Telegram), в модалке выбирается построчно (Choco, Пульс цен).
9. **Бейджи с подсказкой «за что выдан»;** без платных значков (Faire, Keychain).
10. **Счётчики у фильтров и подсказка ослабления:** «если сделать «отсрочку» желательной — +5 поставщиков» (Контур.Компас).
11. **Логистика человеческим языком:** «38 км · 1–2 дня · своя доставка» (Faire).
12. **Заметки команды** в карточке (Rusprofile/Checko) — уже в п. 4.

Не берём: открытая доска заявок, платный доступ/скрытые контакты, «AI дописывает требования», рыночные графики на моках, встроенный чат и десятки фильтров. «Отслеживать поставщика» — в план развития.
